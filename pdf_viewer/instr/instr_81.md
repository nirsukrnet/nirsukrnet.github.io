# Transit tool: PDF OCR → YouTube DB

## Goal
Create a new HTML page that helps “transit” (copy/migrate) OCR snippets stored in Firebase RTDB under:
- `/pdf_viewer_ocr_v1/...`

…into the YouTube database RTDB under:
- `/db_youtube2/ref_youtube_videos`
- `/db_youtube2/youtube_transcripts`

This is a manual/interactive tool: user selects what to copy, reviews/edits metadata, and writes into `/db_youtube2`.

## UI requirements

### A) Source selection (from `/pdf_viewer_ocr_v1`)
- Dropdowns (or searchable selects) to choose:
	- User (or “current signed-in user”)
	- Document (PDF) / docKey
	- Page number
	- OCR entry (rectangle)
- Show preview:
	- OCR text (`text_sw`)
	- Optional translations if present (`text_en`, `text_uk`)
	- Page number and rect coordinates
	- Created/updated timestamps

### B) Target selection / metadata (for `/db_youtube2`)
- Inputs for the target video reference (used to locate/create a row in `ref_youtube_videos`):
	- `videoId` (required)
	- Optional: `title`, `channel`, `lang`, `url`, etc. (whatever your schema expects)
- If the needed metadata does not exist in `/pdf_viewer_ocr_v1`, user must be able to type it manually.

### C) Actions
- Button: **Check target** (loads existing `ref_youtube_videos` + transcripts for the given `videoId`)
- Button: **Create/Update ref_youtube_videos**
- Button: **Append transcript item** (writes OCR text into `/db_youtube2/youtube_transcripts/...`)
- Status area: success/error messages

## Data behavior

### 1) Copy from `/pdf_viewer_ocr_v1`
When a source OCR entry is selected, load the full entry object and prepare a “transit payload” that includes:
- Source identifiers: userKey, docKey, pageNum, entryId
- Source rect and timestamps
- OCR text fields

**Source path (exact)**
- `/pdf_viewer_ocr_v1/{userId}/{docId}/{pageNum}/{entryId}`

### 2) Fill `/db_youtube2/ref_youtube_videos`
If the `videoId` does NOT exist in `/db_youtube2/ref_youtube_videos`:
- Create it using user-provided metadata.

If it DOES exist:
- Do not overwrite important fields by default.
- Allow an explicit “update/merge” option (checkbox) if you want to update missing fields.

**Doc-level info display (required)**
When a document is selected (`/pdf_viewer_ocr_v1/{userId}/{docId}/...`), the tool must show what it can copy/update into `ref_youtube_videos`.

**Source doc-level paths to inspect**
- `/pdf_viewer_ocr_v1/{userId}/{docId}/_ui` (if present)
- Any additional doc-level metadata you store under `/pdf_viewer_ocr_v1/{userId}/{docId}/` (if you add it later)

**What to show / map**
- Always show: `docId` (PDF fingerprint key), `userId`, and the PDF URL (if known by the tool)
- From `_ui` show (if present): `pageNum`, `ocrLang`, `updatedAt`

**How it affects `ref_youtube_videos`**
- The tool must clearly show whether each field will be **created**, **updated**, or **left unchanged**.
- If a field is missing in `/pdf_viewer_ocr_v1`, user must be able to enter it manually.

### 3) Fill `/db_youtube2/youtube_transcripts`
Always append a new transcript item for the selected OCR entry **unless** the same source has already been imported.

**Target path (requested structure)**
- Store transcript items grouped by document:
	- `/db_youtube2/youtube_transcripts/{itemId}`

**Key mapping**
- `itemId` = `docId`
- `docId` is the document key from the source path: `/pdf_viewer_ocr_v1/{userId}/{docId}/...`

**Example**
- Source doc: `/pdf_viewer_ocr_v1/USER123/FP_ABCDEF.../`
- Target group: `/db_youtube2/youtube_transcripts/FP_ABCDEF...`

**Transcript item key (recommended)**
- Under each `{itemId}`, store items by a deterministic key so you can de-duplicate reliably.
- Recommended:
	- `trId = "{pageNum}_{entryId}"`
	- Full path: `/db_youtube2/youtube_transcripts/{itemId}/{trId}`

**Target transcript item shape (minimum required fields)**
```json
{
	"t": "...",
	"text_en": "...",
	"text_sv": "...",
	"pageNum": 37,
	"entryId": "123_456_78_90"
}
```

**Field mapping**
- `text_sv` ← source `text_sw` (PDF viewer stores Swedish in `text_sw` today)
- `text_en` ← source `text_en` (empty string if missing)
- `pageNum` ← selected page number
- `entryId` ← selected entry id
- `t` ← set by user (manual field) OR generated by tool (see note below)

**Note about `t`**
- If `t` is a timestamp: use ISO-8601 string (e.g. `2026-01-26T06:29:29.879Z`).
- If `t` is a "time in video": the tool must ask user to enter it (and define the format you want, e.g. seconds integer).

**De-duplication rule**
- Store `source` info inside each transcript item.
- Before appending, check if an item with the same `(docKey, pageNum, entryId)` already exists for that `videoId`.
- If it exists: show “Already imported” and do not add a duplicate.

## Options / modes
- If the target `videoId` already exists, the tool must support “append only” mode:
	- Only add a new transcript entry (do not touch `ref_youtube_videos`).

## Acceptance criteria
- User can pick an OCR entry and see its full text preview.
- User can provide a `videoId` and check if it exists.
- If `videoId` doesn’t exist: user can create `ref_youtube_videos`.
- User can append the OCR text as a new transcript item.
- Importing the same OCR entry twice does not create duplicates.
